# 멘토링 자동 반영

운영 대상은 환경변수로 지정한 사업관리 마스터와 보고서 폴더다. 프로그램, 캠퍼스, 시트 ID, 폴더 ID는 코드에 고정하지 않는다.

## 처리 흐름

1. 보고서 폴더를 페이지 단위로 조사하고 파일 버전과 회차 탭을 읽는다.
2. `1회차`부터 `4회차`까지의 보이는 탭에서 기업명, 일자, 멘토, 필수 본문을 검증한다.
3. 기업명과 캠퍼스를 마스터의 한 행에 정확히 연결한다.
4. 같은 원본 버전이 짧은 안정 구간 동안 유지된 경우 변경 계획을 만든다.
5. 마스터의 회차 완료, 보고서 작성일, 전체 시수에 필요한 정확한 셀만 기록한다.
6. 이벤트 식별자, 계획 해시, 원본 버전, 쓰기 영수증을 저장하고 다시 읽어 결과를 확인한다.
7. 대시보드와 작업 이력이 새 상태를 조회한다.

고정 주기만 기다려 반영하지 않는다. 필수값 완성과 탭 형식, 원본 안정성, 중복 이벤트를 함께 검사한다. 예약, 빈 탭, 파일명만으로 완료를 판단하지 않는다.

## 역방향 반영

자동 반영 뒤 회차 탭이 삭제되거나 필수값이 제거되면 원복 제안을 만든다. 운영자가 승인하면 해당 자동 이벤트가 기록한 셀 중 현재 값도 그 이벤트의 값과 같은 셀만 되돌린다. 이후 사람이 수정한 값이나 다른 자동 이벤트의 값은 지우지 않는다.

## API와 에이전트

- `GET /api/automation/config`: 현재 대상의 공개 설정
- `GET /api/automation/master`: 마스터 현황
- `POST /api/automation/master`: 기록 미리보기와 실행
- `POST /api/automation/reports/scan`: 보고서 조사
- `POST /api/automation/reports/apply`: 검증된 보고서 반영
- `POST /api/automation/report-names/preview`: 파일명 변경안
- `POST /api/automation/report-names/apply`: 검토된 파일명 변경

Gemini와 Hermes MCP도 같은 서버 함수를 호출하므로 UI, API, 에이전트의 검증 규칙과 이력이 동일하다. 정기 실행은 조회와 보고서 조사만 수행하며 임의의 마스터 쓰기를 허용하지 않는다.

## 실패 처리

원본 버전 변경, 기업명 중복, 기존 값 충돌, API 한도, 쓰기 결과 미확인은 성공으로 처리하지 않는다. 안전하게 재시도할 수 있는 읽기 작업만 재시도하고 불확실한 쓰기는 작업 이력에서 확인한다.
