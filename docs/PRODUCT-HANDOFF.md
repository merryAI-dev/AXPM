# AXPM 멘토링 운영 시스템 인수인계 안내

최종 업데이트: 2026-09-17

AXPM은 기존 Google Drive와 사업관리 마스터 시트를 그대로 사용하면서, 반복적으로 확인하고 옮겨 적던 멘토링 운영 업무를 줄이는 도구입니다.

멘토는 기존 보고서의 회차 탭에 내용을 작성하고, 운영자는 AXPM에서 반영 결과와 누락 항목을 확인합니다. 자동으로 처리된 기록은 활동 이력에 남으며, 원본 보고서가 바뀌었을 때도 운영자가 확인한 뒤 안전하게 되돌릴 수 있습니다.

이 문서는 기능 소개, 에이전트 사용법, 실제로 겪은 문제와 해결 방법, 남은 작업 순서로 구성했습니다. 처음 인수받는 분은 [한눈에 보기](#한눈에-보기)와 [문제 해결](#문제-해결)부터 읽으면 됩니다.

## 한눈에 보기

| 화면(탭) | 구성 | 주로 하는 일 |
|---|---|---|
| 홈 대시보드 | 사업 운영 대시보드 · 에이전트 활동 · 최근 24시간 Drive 변경 | 전체 진행 현황과 자동 처리 결과 확인 |
| Drive · 보고서 | 메일 첨부 수집 · 사업 폴더 파일 탐색 · 최근 24시간 Drive 변경 | 보고서 찾기, 셀 편집 변경안, 메일 첨부 수집 |
| 자동 반영 | 보고서 감시·파일명 통일 · 캠퍼스 사업관리 마스터 | 자동 반영 설정, 점검 실행, 파일명 표준화 |
| 승인 대기함 | 자동 반영 취소 제안 | 보고서 삭제·필수값 제거 시 원복 승인 |
| 작업 이력 | 승인·실행 대기 작업 목록 | Drive 변경안 승인, 실행 결과와 백업 확인 |

모든 화면 오른쪽에는 **운영 에이전트** 패널이 있습니다. 이 패널에서 자연어로 조회나 작업을 요청합니다.

### 이번 업데이트 요약 (2026-09-17)

- **화면 디자인 통합:** 섞여 있던 두 테마를 하나의 디자인 기준으로 정리했습니다. 기본색은 파란색 하나, 상태 표시만 초록·주황·빨강을 씁니다. 최소 글자 크기는 12px입니다. 자세한 기준은 [화면 디자인 기준](#화면-디자인-기준)에 있습니다.
- **Gmail 첨부 수집 추가:** 지정 메일함의 보고서 첨부를 관리 Drive에 모으고 파일명을 통일합니다.
- **상태 표시 개선:** 승인·작업·에이전트 실행 상태를 영어 원문 대신 한국어 라벨과 색 배지로 표시합니다. 성공 알림은 4초 뒤 자동으로 닫힙니다.
- **Gmail 연동 설정:** 기존 Firebase Google 로그인 웹 클라이언트를 재사용하도록 로컬 설정을 넣었습니다. 리디렉션 주소 등록이 남아 있습니다([남은 작업](#현재-상태와-남은-작업)).

## 사업 운영 대시보드

사업관리 마스터 시트의 핵심 현황을 홈에서 바로 확인합니다.

- 전담 멘토링 진행 수와 목표 대비 달성률
- 특화 멘토링 진행 수와 달성률
- 전담·특화 통합 달성률
- 총 참여 기업 수
- 캠퍼스별 회차 진행표, 참여 기업 현황표, 멘토별 담당 기업표, 멘토별 진행 회차표
- 원본 집계표 바로가기

대시보드는 별도 데이터를 만들지 않고, 설정된 마스터의 집계 범위(`AXPM_MASTER_DASHBOARD_RANGE`)를 다시 읽어 수식의 표시값 그대로 보여줍니다. 빈 셀은 `—`로 표시합니다. 화면을 열 때와 자동 반영 직후에 새로 읽습니다.

## 멘토링 보고서 자동 반영

멘토가 기존 보고서 파일에 정해진 회차 탭을 만들고 필수 내용을 작성하면 AXPM이 보고서를 확인합니다.

자동 반영 전에 다음 항목을 함께 검사합니다.

- `1회차`부터 `4회차`까지의 정해진 탭 형식
- 기업명과 캠퍼스
- 멘토명
- 실제 멘토링 일자
- 보고서 작성일
- 참석자와 멘토링 본문 등 필수 내용
- 사업관리 마스터의 기업 및 담당 멘토 일치 여부
- 같은 보고서가 이미 반영되었는지 여부

검증을 통과하면 마스터의 해당 회차 완료 여부와 보고서 작성일을 기록합니다. 회차가 이미 완료되어 있고 작성일도 정상이라면 다시 쓰지 않습니다.

예약 정보, 파일명, 빈 회차 탭만으로는 완료 처리하지 않습니다. 필수값이 빠졌거나 기업과 멘토가 정확히 연결되지 않으면 자동 반영하지 않고, 확인이 필요한 이유를 표시합니다.

백그라운드 감시의 실행 방식과 검증 기록은 [보고서 자동 반영 운영](AUTOMATIC-REPORT-MONITOR.md)에 있습니다.

## 수정 및 삭제에 대한 역방향 반영

자동 반영이 끝난 뒤 멘토가 회차 탭을 삭제하거나 필수 내용을 지우면 AXPM이 변경을 감지합니다.

이때 마스터를 바로 지우지 않고 **승인 대기함**에 "자동 반영 취소" 제안을 만듭니다. 제안 카드에는 대상 파일·회차와 되돌릴 항목(완료 체크·작성일·자동 메모)이 표시됩니다.

- **승인하고 반영 취소:** 해당 자동 반영이 작성했던 셀만 되돌립니다.
- **유지:** 마스터를 그대로 둡니다.

자동 반영 뒤 사람이 직접 수정한 값이나 다른 회차의 기록은 지우지 않습니다. 원본 보고서와 마스터가 어긋났을 때 운영자가 최종 판단하도록 설계했습니다.

## Drive 폴더 탐색 및 검색

운영 대상 Drive 폴더를 AXPM에서 바로 탐색합니다.

- 관리 폴더와 하위 폴더 열람
- 폴더 구조 조사
- 조사한 전체 파일명 검색
- 새 폴더 생성 변경안
- 파일 이름 변경, 복사, 휴지통 이동 및 복원 변경안
- Google Sheets와 XLSX 원본 열기
- 보고서 원본 모양 그대로 보면서 셀 선택·편집 후 변경안 저장

Drive 원본을 바꾸는 작업은 먼저 변경안으로 저장됩니다. 운영자는 **작업 이력**에서 변경 전후 값을 펼쳐 확인한 뒤 승인합니다. 파일을 바꾸는 작업은 실행 전에 변경 전 상태를 비공개 백업(XLSX 또는 JSON)으로 남기며, 작업 카드의 "변경 전 백업 다운로드"로 받을 수 있습니다.

폴더 조사는 한 번에 한 페이지씩 처리하고 체크포인트를 저장합니다. 동시에 두 조사가 겹치지 않도록 2분짜리 잠금을 겁니다. 이 잠금 때문에 콘솔에 400이 찍힐 수 있으며, 자세한 내용은 [문제 해결](#3-driveindex가-400을-반복함)에 있습니다.

## 최근 24시간 Drive 변경

홈과 Drive 탭을 열 때 관리 폴더의 최근 변경 메타데이터를 확인합니다.

- 최근 수정된 파일
- 이름이 변경된 파일과 이전 이름
- 위치 또는 버전이 변경된 파일
- 수정 시각과 확인 시각

최신 50건까지 표시합니다. 파일 단위의 변경 흐름이며, 문서 안의 모든 셀 수정 내역을 뜻하지는 않습니다.

## 보고서 파일명 표준화

보고서 파일명, 보고서 본문, 마스터의 기업 정보를 함께 비교해 표준 파일명 변경안을 만듭니다.

파일명만으로 기업을 확정하지 않습니다. 본문과 마스터에서 기업이 하나로 확인된 경우에만 변경 대상으로 분류합니다. 같은 폴더에 동일한 이름이 있거나 캠퍼스 정보가 충돌하면 실행하지 않습니다.

**자동 반영** 탭의 "파일명 통일 목록 만들기"로 변경 전후 이름을 확인한 뒤 "변경 가능한 파일명 일괄 반영"으로 적용합니다. 파일명 변경 과정에서 보고서 본문은 수정하지 않습니다.

## Gmail 첨부 수집

**Drive · 보고서** 탭 맨 위의 "메일 첨부 수집"에서 사용합니다.

1. 운영자가 "내 Google 계정 연동하기"를 눌러 수집용 계정(`AXPM_GMAIL_ACCOUNT`)의 Gmail 읽기(`gmail.readonly`)에 직접 동의합니다.
2. "새 첨부 가져오기"를 누르면 `AXPM_GMAIL_QUERY` 조건에 맞는 최근 메일을 최대 25개씩 확인합니다.
3. 허용된 첨부(`xlsx`, `pdf`, `docx`, `hwp`, `hwpx`)만 관리 폴더 아래 `[AXPM] 메일 첨부 수집함`에 저장합니다.
4. XLSX 보고서는 본문의 기업·캠퍼스를 마스터와 대조해 표준 파일명으로 바꿉니다.

| 상태 | 뜻 |
|---|---|
| 이름 통일 | 본문·마스터 대조 후 표준 파일명으로 저장됨 |
| 수집 완료 | 저장됐지만 이름 변경 대상은 아님 (XLSX 외 형식 등) |
| 검토 필요 | 기업·회차가 모호하거나 같은 이름이 이미 있어 원본 이름으로 보관됨 |
| 수집 실패 | 저장 중 오류 발생 |

- 같은 메일·첨부는 메시지 ID와 첨부 ID로 확인해 다시 저장하지 않습니다.
- 메일 본문은 서버에 저장하지 않습니다.
- Google 토큰은 AES-256-GCM으로 암호화해 보관합니다.
- "Google 연결 해제"를 누르면 Google 토큰 폐기와 저장 문서 삭제가 함께 이루어집니다.

설정 방법은 [운영 설정 · Gmail 첨부 수집](SETUP.md#gmail-첨부-수집)에 있습니다.

> **조직 전체 위임은 쓰지 않습니다.** 관리자가 서비스 계정에 조직 전체 Gmail 권한을 주는 방식은 권한이 과도해서 제외했습니다. 반드시 운영자가 자기 계정으로 직접 동의합니다.

## 운영 에이전트

Gemini 기반 운영 에이전트가 AXPM의 실제 조회·자동화 도구를 사용합니다. 현재 로컬 환경은 Hermes를 실행기로 씁니다(`AGENT_ENGINE=hermes`).

에이전트가 쓸 수 있는 도구는 다음 범위로 제한됩니다.

- 사업관리 마스터 현황 조회, 확인된 멘토링 기록의 마스터 반영
- 관리 Drive 폴더 조사, 파일 검색, 보고서 셀 읽기
- 특정 보고서의 회차 탭과 필수값 확인
- 보고서 자동 반영 상태 조회, 미리보기, 실행
- 파일명 표준화안 생성 및 적용
- Gmail 첨부 수집 상태 조회와, 요청 시 Drive 수집

마스터 기록은 먼저 변경될 셀을 계산한 뒤 같은 계획으로 실행하고, 다시 읽어 결과를 확인합니다. 정기 조사는 조회와 보고서 감시만 수행하며 임의로 마스터 값을 쓰지 않습니다.

Claude에서는 저장소의 `.claude/skills/axpm-*` 스킬로 같은 도구를 MCP를 통해 사용합니다. 스킬도 서버의 같은 함수를 호출하므로 검증 규칙과 이력은 화면과 동일합니다.

### 요청 예시

| 목적 | 이렇게 요청하세요 |
|---|---|
| 누락 점검 | "이번 주 보고서 누락을 캠퍼스별로 정리해줘" |
| 특정 기업 확인 | "디자인워커스의 전담 회차 완료 여부와 보고서 작성일을 확인해줘" |
| 특정 보고서 반영 | "이 보고서 URL을 읽고 필수 필드와 회차 날짜를 확인해 마스터에 반영해줘. 같은 도구로 재검증하고 변경 셀과 활동 이력을 보고해줘." |
| 파일명 정리 | "01_전담멘토링 폴더의 파일명 통일 목록을 만들어줘. 적용은 하지 마." |
| 메일 첨부 | "메일 첨부 수집 상태를 알려줘. 검토 필요 항목만 정리해줘." |

쓰기가 필요한 요청은 "미리보기만", "적용은 하지 마"처럼 범위를 분명히 적는 것이 안전합니다.

### 처리 방식과 제한

요청 하나는 "모델에 묻기 → AXPM 도구 호출 → 결과를 모델에 전달"을 여러 번 반복합니다. 결과는 요청이 끝난 뒤 한 번에 표시되며, 그동안 화면에는 "확인 중…"만 보입니다.

| 항목 | 한도 | 위치 |
|---|---|---|
| 모델·도구 왕복 | 최대 16회 | `src/lib/hermes-session.ts` |
| 도구 호출 1회 | 120초 | `src/lib/hermes-session.ts` |
| Hermes 실행 전체 | 420초(7분) | `src/lib/hermes-session.ts` |
| 요청 전체 | 8분 | `src/lib/agent.ts` |
| 동시 실행 | 1건 (10분 잠금) | `src/lib/agent.ts` |

실행 중에 다시 요청하면 "에이전트가 작업 중입니다. 완료 후 다시 요청해주세요."가 표시됩니다.

```text
2. 월별 진행 내역 조사 현황
   - 마스터에는 캠퍼스별/멘토별/회차별 집계표는 있으나 별도의 '월별 통계 집계표'는 없습니다.
   - 실제 진행 일자는 각 기업 행(6~94행)의 회차별 보고서 일자 열(1회차 P, 2회차 S, 3회차 V, 4회차 Y)에 있습니다.
   - 87개 기업 211건의 일자 셀을 하나씩 조회하던 중 호출 횟수 제한에 도달해,
     구조 확인과 회차별 총계까지만 정리했습니다.
```

이 사례에서 알 수 있는 점:

- **회차·캠퍼스 집계는 바로 답합니다.** 마스터 대시보드에 집계표가 있기 때문입니다.
- **월별 집계는 지금 도구로 끝까지 못 합니다.** 월별 집계표가 없어서 에이전트가 기업·회차별 날짜 셀을 하나씩 읽어야 하고, 211건이면 16회 왕복 한도를 넘습니다.
- **당장은 범위를 좁혀 요청하세요.** 예를 들어 "남부 캠퍼스 1회차 보고서 작성일만 월별로 세어줘"처럼 요청합니다. 다만 캠퍼스 하나도 수십 건이라 한도에 걸릴 수 있습니다.
- **근본 해결책은 새 도구입니다.** 마스터의 회차별 일자 열(P/S/V/Y)을 한 번에 읽어 월별로 집계하는 조회 도구를 추가하는 것입니다. [남은 작업](#현재-상태와-남은-작업)에 넣어 두었습니다.

## 활동 및 작업 이력

자동화와 운영자 작업은 각각 이력으로 남습니다.

- 자동 반영된 기업과 회차
- 실제 변경된 마스터 셀과 변경 전후 값
- 보고서 점검 결과와 제외 이유
- 역방향 반영 제안과 승인 결과
- 에이전트 요청, 응답, 사용한 도구
- Drive 변경안의 승인 및 실행 상태, 변경 전 백업
- 실행 실패 또는 결과 확인이 필요한 작업

변경 사항이 없는 정기 조사는 활동 목록에 반복해서 쌓이지 않습니다. 실제로 파일을 확인했거나 반영·오류·보완 사항이 생긴 실행을 중심으로 표시합니다.

작업 이력의 상태 배지는 다음과 같습니다.

| 배지 | 뜻 | 운영자 조치 |
|---|---|---|
| 승인 대기 (파랑) | 변경안이 만들어짐 | "변경 내용 · 이력 확인"을 펼친 뒤 승인 또는 반려 |
| 실행 대기 · 실행 중 (파랑) | 승인 후 처리 중 | 기다림. 필요하면 "지금 실행" |
| 확인 완료 (초록) | 실행 후 원본을 다시 읽어 확인함 | 없음 |
| 결과 확인 필요 (주황) | 실행했지만 결과를 확정하지 못함 | 자동 재실행하지 않으므로 원본을 확인하고 필요하면 새로 요청 |
| 실행 전 실패 (빨강) | 실행 전에 막힘 | 오류 문구 확인 |

## 계정 및 접근 권한

- **로그인:** Firebase Google 로그인을 씁니다. 허용된 회사 도메인(`ALLOWED_DOMAINS`) 또는 개별 운영 계정(`ALLOWED_EMAILS`)만 업무 화면과 API에 접근할 수 있습니다.
- **Drive·Sheets:** 서버의 운영 서비스 계정으로 연결합니다. 서비스 계정은 지정된 관리 폴더 안에서만 파일을 조회·변경하고, 폴더 밖 파일과 바로가기 대상에는 접근하지 않습니다.
- **Gmail:** 서비스 계정이 아니라 운영자 개인의 OAuth 동의로 연결합니다([Gmail 첨부 수집](#gmail-첨부-수집)).
- **요청 출처 확인:** 저장·실행 같은 POST 요청은 브라우저 주소가 `APP_ORIGIN`과 정확히 같아야 통과합니다.
- **비밀값:** Gemini API 키, OAuth 비밀, 정기 실행 비밀은 서버 Secret Manager(로컬은 `.env.local`)에만 둡니다. 브라우저와 공개 설정 응답에는 전달하지 않습니다.

## 운영 흐름

1. 멘토가 기존 보고서 파일의 회차 탭에 멘토링 내용을 작성합니다. 메일로 제출한 보고서는 메일 첨부 수집으로 Drive에 모읍니다.
2. AXPM이 탭 형식과 필수값, 기업, 멘토, 날짜를 확인합니다.
3. 검증된 내용만 사업관리 마스터에 자동 반영합니다.

6. 보고서가 삭제되거나 불완전해지면 승인 대기함에 원복 제안이 생깁니다.
7. 운영자는 예외 항목, 승인 대기함, 작업 이력만 확인합니다.

## 문제 해결

2026-09-17 로컬 운영 중 실제로 발생한 사례입니다. 브라우저 개발자 도구의 Console·Network 탭에서 같은 증상이 보이면 아래를 따르세요.

### 1. 저장·연동 버튼이 403으로 실패함

```text
:3000/api/mail/oauth/start:1  Failed to load resource: the server responded with a status of 403 (Forbidden)
:3000/api/drive/index:1       Failed to load resource: the server responded with a status of 403 (Forbidden)
```

화면 문구는 `허용되지 않은 요청 출처입니다.`입니다.

- **원인:** 서버는 POST 요청의 `Origin`이 `APP_ORIGIN`과 정확히 같은지 확인합니다(`src/lib/firebase.ts`). 로컬 설정은 `APP_ORIGIN=http://127.0.0.1:3000`인데 브라우저에서 `http://localhost:3000`으로 열면, 같은 컴퓨터라도 다른 출처로 판단합니다. 그래서 조회(GET)는 되고 저장·연동(POST)만 실패합니다.
- **해결:** 주소창에 **http://127.0.0.1:3000** 으로 접속합니다. 로그인은 주소별로 저장되므로 한 번 다시 로그인할 수 있습니다.
- **권장하지 않는 방법:** `APP_ORIGIN`을 `localhost`로 바꾸는 것입니다. Gmail 연동 후 돌아오는 주소도 이 값으로 만들어지므로, Google Cloud에 등록한 리디렉션 주소와 어긋나 연동이 깨집니다.
- **구분할 점:** 문구가 `허용된 운영 계정이 아닙니다.`라면 출처가 아니라 계정 허용 목록(`ALLOWED_DOMAINS`/`ALLOWED_EMAILS`) 문제입니다.

### 2. "내 Google 계정 연동하기"가 503으로 실패함

```text
client.ts:22  POST http://127.0.0.1:3000/api/mail/oauth/start 503 (Service Unavailable)
```

- **원인:** Gmail 연동 설정이 비어 있습니다(`src/lib/google-user-oauth.ts`). 다음 셋 중 하나라도 없으면 503을 반환합니다.
  - `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`
    - 없으면 `개인 Google 연동 설정이 완료되지 않았습니다.`
  - `OAUTH_TOKEN_ENCRYPTION_KEY`(32바이트 base64)
    - 없으면 `Google 연결 토큰 암호화 설정이 필요합니다.`
  - 비슷한 이름의 `TOKEN_ENCRYPTION_KEY`는 별개 설정이라 대신 쓰이지 않습니다.
- **해결:** Firebase Google 로그인이 이미 쓰는 웹 클라이언트를 재사용합니다. gcloud로 값을 읽는 방법은 [운영 설정](SETUP.md#gmail-첨부-수집)에 있습니다. 값을 넣은 뒤 콘솔에서 리디렉션 주소를 등록하고, 개발 서버가 `.env.local`을 다시 읽었는지 확인합니다. 503이 계속되면 서버를 재시작합니다.
- **"그냥 권한 허용만 받으면 되지 않나?"** 안 됩니다. Google 동의 화면 자체가 "어느 앱이 요청하는지"를 OAuth 클라이언트로 식별합니다. 클라이언트 등록은 앱당 처음 한 번만 필요하고, 그 뒤 각 운영자는 버튼으로 자기 계정을 연결합니다.

### 3. drive/index가 400을 반복함

```text
forward-logs-shared.ts:120 [HMR] connected
:3000/api/drive/index:1  Failed to load resource: the server responded with a status of 400 (Bad Request)
:3000/api/drive/index:1  Failed to load resource: the server responded with a status of 400 (Bad Request)
:3000/api/drive/index:1  Failed to load resource: the server responded with a status of 400 (Bad Request)
:3000/api/drive/index:1  Failed to load resource: the server responded with a status of 400 (Bad Request)
```

- **원인(추정):** 폴더 조사 잠금과의 충돌입니다.
  - 폴더 조사는 2분짜리 잠금을 겁니다(`src/lib/workspace/indexer.ts`). 잠금 중에 다시 요청하면 `폴더를 조사 중입니다.`라는 일반 오류가 나고, API가 이를 400으로 보냅니다.
  - "최근 24시간 Drive 변경" 패널은 홈·Drive 탭을 열 때마다 조사를 시작하고, 이 응답을 받으면 2.5초마다 다시 시도합니다(`src/app/drive-history.tsx`).
  - 그래서 400이 몇 번 찍힌 뒤 조사가 정상적으로 이어집니다.
- **확인:** Network 탭에서 400 응답을 열어 Response가 `{"error":"폴더를 조사 중입니다."}`인지 봅니다. 이 메시지라면 대기 중일 뿐 기능 문제는 아닙니다. 다른 메시지라면 원인이 따로 있습니다.
- **알려진 부작용:** Drive 탭의 "전체 폴더 조사" 버튼은 이 대기 응답을 처리하지 않습니다. 패널이 조사 중일 때 누르면 오류 배너가 뜰 수 있습니다. 개선안은 [남은 작업](#현재-상태와-남은-작업)에 있습니다.

### 4. 에이전트 요청이 한참 걸림

- **원인:** 요청 하나가 모델 호출과 AXPM 도구 호출을 최대 16회 반복하고, 결과는 끝난 뒤에만 표시됩니다. 마스터·Drive를 읽는 도구는 호출마다 수십 초가 걸릴 수 있습니다.
- **확인:** 실행 중이면 `hermes chat` 프로세스가 떠 있고, Google API와 로컬 3000번 서버에 연결된 상태입니다.

  ```sh
  ps -Ao pid,etime,command | grep "hermes chat" | grep -v grep
  ```

  CPU가 0%에 가까우면 계산이 아니라 모델·도구 응답을 기다리는 중입니다.
- **해결:** 최대 8분 안에 결과나 오류가 돌아옵니다. 8분이 지나도 "확인 중…"이면 서버 로그를 확인합니다. 요청 범위를 좁히면 빨라집니다.

### 5. 에이전트 결과가 "호출 횟수 제한"으로 일부만 나옴

위 [월별 조사 사례](#실제-사례-월별-전담멘토링-조사-2026-09-17)처럼 수백 개의 셀을 하나씩 읽어야 하는 요청은 16회 왕복 한도에 걸립니다. 범위를 좁혀 다시 요청하거나, 집계 전용 도구 추가를 검토합니다.

### 6. Claude 스킬이나 Claude Gmail 커넥터로 Gmail 연동을 건너뛸 수 있나?

- **AXPM 스킬(`axpm-mail-intake`):** 건너뛸 수 없습니다. 스킬도 서버의 같은 메일 수집 함수를 호출하고, 그 함수는 운영자 OAuth 토큰으로만 Gmail에 접근합니다. 웹 연동 전에는 `connected: false`를 받고 연동을 안내합니다.
- **Claude의 Gmail 커넥터:** Claude가 대화 중에 사용자의 Gmail을 직접 읽는 **별도 경로**입니다. 메일 검색·요약에는 쓸 수 있지만, AXPM 서버의 자동 수집·Drive 저장·파일명 통일·백그라운드 점검에는 연결되지 않습니다. 연결은 Claude Code에서 `/mcp` → **claude.ai Gmail**을 선택합니다.

## 화면 디자인 기준

화면을 수정하거나 새 화면을 추가할 때 지킬 기준입니다. 모든 스타일은 `src/app/globals.css` 한 파일에 있습니다.

- **색은 토큰만 씁니다.**
  - 기본색: `--accent`, `--accent-strong`, `--accent-soft`
  - 상태: `--ok`/`--ok-soft`(성공), `--warn`/`--warn-soft`(확인 필요), `--danger`/`--danger-soft`(실패)
  - 면·선·글자: `--surface`, `--surface-2`, `--line`, `--ink`, `--body`, `--muted`
  - 예전 초록 테마 색(`#244e3d`, `#dcf09a`, `#e8ede2`)은 쓰지 않습니다.
- **글자 크기:** 최소 12px입니다. 크기 단계는 12(보조) / 13 / 14(본문) / 16(소제목) / 18(패널 제목) / 26(페이지 제목)입니다.
- **기존 클래스를 재사용합니다.**

  | 용도 | 클래스 |
  |---|---|
  | 패널 | `.panel`, `.panelTitle` |
  | 버튼 | `.primary`, `.secondary`, `.textButton` |
  | 상태 배지 | `.badge` + `.green`/`.amber`/`.blue`/`.red` |
  | 알림 | `.banner.error`, `.banner.success`, `p.error` |
  | 안내문 | `.hint` |
  | 표 | `.tableWrap` 안에 `table` (대시보드 숫자표는 `.dashboardTable`) |
  | 요약 숫자 | `.stats`(큰 카드), `.metricRow`(작은 칸) |
  | 목록 | `.fileRow` + `.fileInfo`, 버튼 줄은 `.buttonRow` |

- **상태 문구는 한국어로 씁니다.** 서버 상태값(`pending`, `done` 등)을 화면에 그대로 노출하지 않고, 라벨·색 매핑(`page.tsx`의 `proposalStatus`, `runStatus`, `jobs-panel.tsx`의 `labels`)을 거칩니다.
- **확인 방법:** 데스크톱(1512px)과 모바일(390px) 너비에서 가로 스크롤, 겹침, 스타일 없는 요소가 없는지 봅니다. 700px 이하에서는 사이드바가 상단 가로 메뉴로 바뀝니다.

| 3 | 폴더 조사 대기 응답 정리 | 개발 | 잠금 중 400 대신 "조사 중" 정상 응답을 주고, 패널과 "전체 폴더 조사" 버튼이 같은 방식으로 기다리게 함 |
| 4 | 월별 집계 조회 도구 | 개발 | 마스터 회차별 일자 열(P/S/V/Y)을 한 번에 읽어 월·캠퍼스·회차별로 집계. 에이전트·대시보드 공용 |
| 5 | 에이전트 진행 표시 | 개발 | 요청을 작업으로 등록하고 사용 중인 도구와 진행 상황을 실시간 표시 |
| 6 | 병합 브랜치 push | 담당자 | `dac4c75`는 아직 로컬에만 있음 |
| 7 | 자동 반영 탭 버튼 정리 | 디자인·개발 | 보고서 감시 버튼 5개가 두 줄로 흩어져 있어 주요 동작 위주로 묶기 |

Gmail 연동 설정은 로컬 `.env.local`에만 있습니다. 배포 환경에는 `GOOGLE_OAUTH_CLIENT_SECRET`과 `OAUTH_TOKEN_ENCRYPTION_KEY`를 Secret Manager로 따로 주입해야 합니다. 배포용 암호화 키는 로컬 키를 재사용하지 말고 새로 만드세요. 로컬 키가 노출되면 배포 서버에 저장된 Google 토큰까지 풀릴 수 있기 때문입니다.

## 운영 준비 상태

Google Drive와 사업관리 마스터 연결, Firebase 로그인과 데이터 저장, Gemini 비밀 저장, 자동 보고서 감시, 비공개 백업 저장소, 배포용 컨테이너 저장소가 준비되어 있습니다.

배포 전 점검에서 결제 연결, 필수 Google Cloud API, 실행 서비스 계정, Firestore, 비공개 파일 버킷, Artifact Registry, Secret Manager, Google 로그인을 모두 확인했습니다.

실제 서비스 배포 후에는 다음 순서로 최종 확인합니다.

1. 배포 주소를 Firebase 승인 도메인과 OAuth 리디렉션 URI에 추가합니다.
2. 배포 환경의 `APP_ORIGIN`을 배포 주소와 정확히 맞춥니다.
3. 허용 계정으로 로그인해 마스터 조회, 보고서 자동 반영, Gmail 연동을 확인합니다.

멘토는 기존 양식을 바꾸지 않고 보고서를 작성하고, 운영자는 반복 입력 대신 누락과 예외 확인에 집중할 수 있습니다. AXPM은 원본 Drive와 마스터 시트를 중심으로 자동 반영, 검증, 승인, 이력 확인이 하나의 흐름으로 이어지게 합니다.
