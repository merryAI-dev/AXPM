# 대화 요청에서 상시 업무 점검으로

운영자가 매번 요청을 작성하는 대신 운영 이벤트를 받아 근거를 수집하고 다음 조치를 정하도록 발전시킨다. 사람은 모니터링의 시작 버튼보다 예외와 외부 영향이 있는 결정에 관여한다. 아래에서 현재 구현과 후속 구현을 구분한다.

## 현재 구현

- `scripts/worker.mjs`: 영속 큐의 작업 하나를 처리한다. 큐가 비어 있고 `AXPM_MONITOR_WORKSPACE=true`이면 폴더 조사 한 페이지를 진행한다.
- `/api/cron`의 workspace 모드: 사용자 `monitoringEnabled` 설정을 확인하고 조사 체크포인트를 저장한다. 조사가 완료되면 모델 설정이 있을 때 Hermes 점검을 큐에 넣는다.
- mentoring 모드: 신청 시트를 동기화한 다음 전담·특화 횟수와 누락을 실제 근거로 점검한다.
- 정기 Hermes 실행: 읽기 전용 MCP 권한으로 점검한다. 모델이 직접 승인하거나 쓰기 작업을 실행할 수 없다.
- 승인한 파일 변경: 버전 확인·백업·실행·재조회가 있다. 불확실한 실행은 자동 재시도하지 않는다.
- Cloud Run Job/Scheduler 설정 코드는 있으나 사용자 요청으로 배포하지 않았다. 현재 자동 상시 운영 중이라는 의미가 아니다.

## 후속 구현 계약

### 1. 변경 감지와 이벤트 저장

작은 사업에서는 예약 폴링 + Firestore outbox부터 시작한다. Drive Changes API 체크포인트와 Sheets 범위 값의 해시를 저장하고 변경이 있을 때만 `source.changed`를 기록한다. Drive webhook은 깨우는 신호로 사용하고 실제 변경 내용은 인증 API로 다시 읽는다. 규모와 여러 소비자 요구가 생기면 Pub/Sub 또는 Kafka로 전달 계층을 교체한다.

이벤트 필드: `uid`, `eventId`, `sourceId`, `sourceVersion`, `range`, `contentHash`, `observedAt`, `policyVersion`. 멱등 키는 `uid/sourceId/contentHash/policyVersion`이다. 체크포인트는 이벤트 영속화 이후에 이동한다. 주기적인 전체 대조로 누락 이벤트를 복구한다.

### 2. 근거 수집과 판단

횟수·잔여 시수·취소·중복·마감은 코드로 계산한다. Hermes/Gemini는 해당 변경의 의미, 누락 원인, 추가로 읽어야 할 자료와 우선순위를 판단한다. 근거가 부족하면 다음 조회를 수행하거나 해당 항목만 확인 대기로 둔다. 파일명만으로 완료를 확정하지 않는다.

예시: 신청행 추가 → 기업/멘토 식별 → 남은 시수와 일정 충돌 확인 → 보고서 대상 연결 → 문제 없으면 관찰 상태 갱신, 예외가 있으면 근거 셀·문제·권고 조치를 묶는다.

### 3. 권한에 따른 실행

| 처리 | 정책 |
| --- | --- |
| 읽기·대조·지표 갱신·내부 점검 결과 저장 | 사전 설정한 범위에서 자동 |
| 보고서 초안과 메일 초안 준비 | 근거 있는 초안 생성 도구를 별도로 부여 |
| 메일 발송·일정 확정·티켓/시수 변경·원본 수정 | 구체적 diff와 수신자/대상/근거로 승인 요청 |
| 판단 근거 불충분·버전 충돌·중복 여부 불명 | 해당 건만 담당자 확인 |

현재 정기 실행의 읽기 전용 키에는 초안 생성 권한도 없다. 초안 자동화를 추가할 때는 `draft:create` 같은 분리된 권한을 도입한다. 전체 쓰기 권한이나 쉘을 주는 방식으로 확장하지 않는다.

### 4. 승인 이후 재확인

상태는 `observed → investigating → ready / needs_input → awaiting_approval → executing → verified / uncertain`으로 저장한다. 승인에는 근거 버전과 만료를 포함하고 실행 전 다시 확인한다. 파일·시트는 현재의 재조회 검증을 사용한다. 메일은 메시지 ID, 일정은 이벤트 ID로 결과를 확인한다. 기록을 남기고 후속 확인 시간을 예약한다.

같은 누락을 매 주기 새 알림으로 만들지 않도록 `caseId`, 마지막 관찰 버전, 담당자, 기한, 알림 이력을 저장한다. 해결된 사례만 닫고 미해결 상태는 시간에 따라 우선순위를 조정한다.

## 평가 기준

고정된 합성 시트 변화로 미신청·중복·취소·보고서 누락 탐지 정확도를 검사한다. 같은 이벤트를 재전달해도 사례·초안이 하나만 생성되어야 한다. 소스 버전이 바뀌면 오래된 승인이 실행되지 않아야 한다. 예산/도구 호출/재시도 한도와 오류를 기록한다. 모델 답변이 아니라 실제 업무 상태의 개선, 불필요한 사람 호출 수, 승인까지의 시간, 검증된 완료율로 평가한다.

HWPX 출력은 이 흐름의 문서 생성 도구로 연결한다. 스킬에 적힌 지시만으로 실행 권한이 생기지는 않는다. 요청 명세를 검증하고 격리된 실행기로 넘기며, 품질 리포트와 산출물 해시를 작업 결과로 저장하는 전용 MCP 도구가 다음 구현 단위다.
